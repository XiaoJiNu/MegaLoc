## 0. 一句话总览

MegaLoc 做视觉位置识别(VPR): 输入一张 RGB 图, 输出一个 8448 维、L2 归一化的全局描述子向量;
两张图的相似度 = 两个向量的点积(余弦)。结构 = **DINOv2 ViT-B/14 骨干** 提特征 + **SALAD 式最优传输聚合头** 把几百个局部特征压成一个向量 + **一层 Linear 降维**。

```
图像 [B,3,H,W] ──DINOv2──▶ (patch特征图 [B,768,h,w], cls [B,768])
                                    │
                          FeatureAggregator(OT软聚类)
                                    ▼
                            [B, 16640]
                                    │ Linear 16640→8448 + L2
                                    ▼
                            描述子 [B, 8448]
```

## 1. class MegaLoc (megaloc_model.py:400-462) —— 主模型

### 1.1 __init__ 组装了什么 (行 420-444)

```python
self.backbone   = DINOv2()                       # ViT-B/14, 86.6M 参数
self.aggregator = Aggregator(...)                # 聚合头, 142.1M 参数
self.l2norm     = L2Norm()                       # F.normalize(x, p=2, dim=1)
self.salad_out_dim = num_clusters*cluster_dim + token_dim = 64*256+256 = 16640
```

默认超参: `feat_dim=8448, num_clusters=64, cluster_dim=256, token_dim=256, mlp_dim=512`。
注意 `FeatureAggregator` 类自己的默认 cluster_dim 是 128(行 85, SALAD 原论文配置), 但 MegaLoc 通过 agg_config 显式传入 256 —— 以 MegaLoc 的默认值为准。

参数量实测: 总 228.6M(≈2.29 亿个参数), 其中骨干 86.6M、聚合头 142.1M(大头是 `linear` 16640×8448≈140.6M 的降维矩阵)。
注意区分"参数量"与"权重文件大小": 权重为 fp32, 每个参数 4 字节, 228.6M × 4B = 914,558,212 B = 873 MiB —— 即 HF 缓存里 model.safetensors 的 800 多 M(scripts/reproduce_inference.py:36 那份), 两者是同一个数, 单位不同。

### 1.2 forward (行 446-462)

**输入**: `[B, 3, H, W]` RGB 图像张量, 已经过归一化(脚本侧 ToTensor + ImageNet mean/std, 见 scripts/reproduce_inference.py:64 build_transform, Resize 到 322×322)。
**输出**: `[B, 8448]`, 每行 L2 范数 = 1(实测)。

三步逻辑:

```python
if h % 14 != 0 or w % 14 != 0:          # 行 456-459: 兜底
    h, w = round(h/14)*14, round(w/14)*14
    images = tfm.resize(images, [h, w], antialias=True)
features = self.aggregator(self.backbone(images))   # 骨干→聚合头
return self.l2norm(features)                        # 行 461
```

- 分辨率必须被 patch_size=14 整除(Conv 切块不留边角), 否则模型内部自动 resize 到最近的 14 倍数 —— 实测喂 (1,3,300,400) 也能出 [1,8448]。
- 除此之外骨干对任意分辨率工作(位置编码插值, 见 2.3), 322 和 518 实测都正常。

### 1.3 Aggregator 包装层 (行 389-397)

```python
self.agg    = FeatureAggregator(**agg_config)      # OT聚合 → [B,16640]
self.linear = nn.Linear(16640, 8448)               # 降维瓶颈
```

MegaLoc 相对 SALAD 论文的唯一结构改动: 在聚合头后面加了这个 Linear, 把 16640 压到 8448(=66×128)。fp32 下一条描述子 33KB, 比 SALAD 原生省一半存储/检索带宽。8448 就是库检索时的向量维度。

## 2. DINOv2 骨干 (megaloc_model.py:270-372) —— 特征提取器

标准 ViT-B/14(权重兼容官方 DINOv2), 只是为"输出空间特征图 + cls token 两路"做了适配。

**输入** `[B,3,H,W]` → **输出** `(patch_features [B,768,H/14,W/14], cls_token [B,768])`。

### 2.1 PatchEmbedding (行 161-175): 切块

```python
nn.Conv2d(3, 768, kernel_size=14, stride=14)
```

每个 14×14 像素块被这一个卷积核"读"成一个 768 维向量(等价于 Linear(14·14·3=588→768) 展平后)。
H=W=322 时: 23×23=**529 个 token**, `[B,3,322,322] → [B,529,768]`。
H=W=518(训练分辨率): 37×37=1369 个 token。

### 2.2 CLS token 与位置嵌入 (行 296-301)

- `cls_token`: `[1,1,768]` 可学习参数, batch 内共享, 前向时 expand 拼到序列头部 → `[B,530,768]`。它是全局摘要占位符, 靠自注意力把整图信息聚合到自己位置。
- `pos_embed`: `[1,1370,768]`(1369 patch + 1 cls), 按 518 分辨率训练。

### 2.3 interpolate_pos_encoding (行 312-343): 换分辨率不重训

输入 322×322 时只有 23×23 格, 但位置编码存的是 37×37 格。做法: 把 patch 位置嵌入 reshape 成 `[1,768,37,37]` 的"图像", 双三次插值(scale 因子 `(w0+0.1)/37`, 0.1 是偏移平滑项)到 `[1,768,23,23]`, 再摊平回来和 cls 的位置编码拼接。所以骨干对分辨率是弹性的。

### 2.4 TransformerBlock ×12 (行 242-267): 主体

Pre-Norm ViT 层, 带 CaiT/DINOv2 风格的 LayerScale:

```python
x = x + LayerScale( Attn( LayerNorm(x) ) )     # ls1: 逐通道可学习缩放γ, 初值1e-5
x = x + LayerScale( MLP(  LayerNorm(x) ) )     # 让训练初期每层接近恒等
```

- **MultiHeadAttention** (行 189-217): dim=768, 12 头×head_dim 64。一个 `Linear(768→2304)` 同时出 Q/K/V, reshape 成 `[B,12,530,64]`, 调 `F.scaled_dot_product_attention`(内部 1/√64 缩放, 数学上即 softmax(QKᵀ/8)V), 拼回 `[B,530,768]`。
- **MLP** (行 220-239): `768 → 3072 (GELU) → 768`, mlp_ratio=4。
- **LayerScale** (行 178-186): 就是一个可学习的逐通道乘法 `x*γ`。

维度全程不变: `[B,530,768]` 进, `[B,530,768]` 出, ×12。

### 2.5 forward 收尾拆两路 (行 364-372)

```python
x = self.norm(x)                    # 最后 LayerNorm
cls_token    = x[:, 0]              # [B,768]   全局摘要
patch_tokens = x[:, 1:]             # [B,529,768]
patch_features = reshape(B,23,23,768).permute(0,3,1,2)   # [B,768,23,23] 当特征图用
```

reshape 按行优先还原 token→网格的行列对应(patch_embed 的 flatten(2) 是行优先, 这里对称还原)。两路都交给聚合头。

## 3. FeatureAggregator (megaloc_model.py:67-153) —— OT 软聚类聚合头

### 3.1 它在做什么(原理)

骨干给出 529 个局部向量 + 1 个全局向量。聚合头要把 529 个压成 1 个, 方式不是平均, 而是**带垃圾桶的软聚类记账**: 预定义 64 个语义簇("天空""路面""建筑立面"…… 簇由训练学出), 用最优传输(Sinkhorn)决定每个 patch 往哪些簇各记多少账, 最后 64 个簇各自的加权平均向量拼起来当描述子。

比平均好在哪: 平均会把小目标(一块特色招牌)稀释掉; 记账保留"这 529 块里**存在哪些种类**的东西、各类长什么样", 对视角变化、局部遮挡更鲁棒。dustbin(垃圾桶)让无信息 patch(糊掉的天空、运动模糊块)不进任何簇, 不污染描述子。

### 3.2 三条分支 MLP (行 104-123) —— 对特征图 [B,768,23,23] 逐 patch 独立小 MLP

用 1×1 Conv 实现(作用在空间特征图上, 每个位置独立, 等价于 Linear 但少一次 reshape):

| 分支 | 定义 | 输入→输出 | 含义 |
|---|---|---|---|
| 内容路 `cluster_features` (行 110) | Conv1×1 768→512, Dropout(0.3), ReLU, Conv1×1 512→256 | [B,768,23,23] → flatten → [B,256,529] | 每个 patch"长什么样"(记账内容) |
| 打分路 `score` (行 116) | 同结构, 512→64 | [B,768,23,23] → [B,64,529] | 每个 patch 对 64 簇的原始亲和分 |
| 全局路 `token_features` (行 105) | Linear 768→512→256 (ReLU) | cls [B,768] → [B,256] | 整图摘要向量 |

另有 `self.dust_bin = nn.Parameter(1.0)`(行 123): 一个可学习标量, 是 dustbin 那行的固定打分。

### 3.3 Sinkhorn 最优传输 (get_matching_probs 行 50-64 + log_otp_solver 行 22-45)

打分矩阵 `p [B,64,529]` 只是"原始分数", 不能直接当权重用。Sinkhorn 把它变成合法**运输计划**: 每列(patch)分给 64 簇+dustbin 的比例合计为 1, 每行(簇)接收的总量也被均衡(均匀边际), 即一个双随机化的软分配。这就是它比 softmax-per-patch 强的地方——防止"所有 patch 都涌进同一个簇"的塌缩。

逐步(均为行号):

1. 行 54-56: 分数矩阵补一行 dustbin → `S_aug [B,65,529]`, dustbin 行填可学习标量。
2. 行 59-62: 目标边际 `log_a`(65 行侧)、`log_b`(529 列侧)都取均匀分布 `-log(n+m)`; 行 61 给 dustbin 行额外加 `log(n-m)` 修正——垃圾桶容量比正常簇大, 允许更多垃圾进。
3. 行 37-45(log_otp_solver): 在 log 域交替做行/列 logsumexp 归一(`u`、`v` 两组对偶变量), `reg=1.0` 是熵正则温度, **`num_iters=3` 轮**(MegaLoc/SALAD 用 3 轮就够, 不用收敛到底)。
4. 行 63-64: 返回 log 域运输计划 `log_P [B,65,529]`(再减 norm 还原量纲)。

回到 forward(行 141-143): `p = exp(log_P)` 得概率计划, `p[:, :-1, :]` **删掉 dustbin 行**——垃圾不进任何簇的账。

### 3.4 按簇汇总与拼接 (行 145-153)

```python
torch.einsum("bdn,bkn->bdk", f, p)
# 簇 k 的向量 = Σ_n (patch n 的内容向量 f[:,n] × 运输权重 p[k,n])
# [B,256,529] × [B,64,529] → [B,64,256]
```

即每个簇得到"成员 patch 内容向量的加权和"。然后:

```
F.normalize(t)                    # [B,256]  cls路, 自身L2
F.normalize(einsum结果, dim=1)     # 每簇256维各自L2 → flatten → [B,16384]
cat → [B,16640] → 整体F.normalize → 输出
```

分段归一(簇内、cls、整体各一次)防止某簇权重范数过大垄断相似度。

### 3.5 输出

`[B, 16640]`, 交给 Aggregator.linear → `[B,8448]` → MegaLoc.l2norm → 最终描述子。

## 7. 量化(int8/fp16): 存储与速度实测 (RTX 5090, mv2d, 322×322)

### 7.1 存储

| 方案 | 权重文件 | 说明 |
|---|---|---|
| fp32(现状) | 873 MiB | 228.6M 参数 × 4B |
| fp16 | ≈437 MiB | ×2B, 精度基本无损 |
| int8 全理论下限 | ≈218 MiB | ×1B |
| int8 实际(PyTorch quantize_dynamic) | ≈226 MiB | 只能量 Linear(本模型 Linear 占 141M/228.6M, 大头正好被吃到); Conv 骨干仍 fp32 |

描述子库侧更值得量化: 8448 维 fp32=33KB/条 → int8=8.4KB/条(省4×), 且检索 `q@DB.T` 可走 int8 GEMM。

### 7.2 速度(实测)

| 配置 | fp32 | fp16(autocast) | 加速比 |
|---|---|---|---|
| GPU B=32 | 638 ms | 89 ms | **7.2×** |
| GPU B=1 | 19.1 ms | 6.5 ms | **2.9×** |
| CPU(8线程) B=1, int8 仅 Linear | 329 ms | —(int8: 175 ms) | 1.9× |

精度: int8-dynamic(Linear) 描述子与 fp32 余弦 = **0.99995**, 基本无损。

### 7.3 结论(部署建议)

1. **GPU 上直接上 fp16**: `with torch.autocast("cuda", dtype=torch.float16)` 一行, 2.9-7.2×, 不需要量化流水线。
2. **int8 在 GPU 上用 PyTorch 原生 dynamic quant 无加速**(那是 CPU fbgemm 路径); 要在 GPU 上让 int8 快过 fp16 得上 TensorRT/ONNX, ViT 注意力部分通常仅再挤 1.2-1.5×, 工程量大收益不确定 → 等有真实吞吐瓶颈再说。
3. **描述子库存 int8**(fp32 向量除以 max-abs 存 qint8 即可, 检索时点积多除一个公共 scale, 不影响 top-K 排序)。
4. 坑: 本模型 `get_matching_probs`(megaloc_model.py:50) 内部 `torch.tensor(...)` 硬编码 fp32, **`model.half()` 整模型转半精度会在 :148 的 einsum 处 dtype 冲突崩掉**; autocast 不受影响(它把那段自动提升到 fp32)。转 fp16 请走 autocast 或修那两行常量的 dtype。
